## Convenzioni della KB
- Un file per soggetto, nome = slug stabile; per gli esercizi lo slug coincide con `scheda/scheda.json`.
- Frontmatter YAML con `tipo` (esercizio / attrezzo / concetto / decisione), `slug`, `aggiornato`; campi aggiuntivi per tipo come nei file esistenti.
- Link relativi in Markdown standard; niente wikilink né sintassi solo-Obsidian nelle note lette dagli agenti.
- Le foto di setup degli attrezzi in `kb/esercizi/foto/<slug>.jpg`, referenziate dalla nota esercizio.
- Una decisione non si modifica: se cambia, nuova nota con `stato: sostituisce <slug precedente>` e la vecchia passa a `stato: superata`.
